# QuadraConverter Production Rebuild v4

## What is fixed

- Google OAuth uses the Supabase Google provider and shows a clear setup message when the provider is disabled.
- Email password recovery uses Supabase `resetPasswordForEmail`.
- Free users receive 5 conversion credits per day through database RPCs.
- Format Converters are not a standalone category; conversion tools remain grouped inside the relevant tool category.
- Image to SVG is included.
- Global layout removes the footer/blank-space issue and keeps the page shell at `100svh`.
- Signature Suite contains 16 premium tools.
- Signature Suite is included in the normal daily conversion-credit model; the runtime does not require a separate Signature Suite plan.
- PDF/DOCX/image signing, signature drawing/typing/upload, placement, multi-page signing, requests, signer order, templates, SHA-256 hashing, ECDSA P-256 integrity proofs, verification, download/share and audit records.
- Supabase migration adds signature requests, signer records, audit events and Signature Suite billing.
- Signature requests create token-protected signer links; optional Resend email delivery is included through the Supabase Edge Function.

## Run frontend

```bash
npm install
npm run dev
```

Create `.env` from `.env.example`:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_ANON_KEY
VITE_CONVERTER_API_URL=http://localhost:8000
```

## Supabase

Run the SQL migrations in `supabase/migrations/` in Supabase SQL Editor.

### Google Sign-In

Supabase Dashboard -> Authentication -> Providers -> Google -> Enable.

Create Google OAuth credentials in Google Cloud Console and add the client ID/secret to Supabase.

For local development, add:

- Site URL: `http://localhost:5173/`
- Redirect URL: `http://localhost:5173/`

For production, use your real HTTPS domain and the callback URL shown by Supabase.

The error `Unsupported provider: provider is not enabled` is generated by Supabase when Google is not enabled. It cannot be fixed by frontend code alone.

## Password reset

Supabase Dashboard -> Authentication -> URL Configuration.

Add your local and production reset URLs. The frontend sends the reset email with a `?reset=1` callback.

For production, configure SMTP/email delivery in Supabase.

## Signature Suite

All 16 Signature Suite tools are premium. The included plan is `signature_suite` at ₹299 for 30 days.

The current UPI payment model creates a payment request and waits for admin UTR verification.

### Cryptographic integrity

The browser creates an ECDSA P-256 key pair and signs the SHA-256 document hash. The private key is never exported by the application. The proof is downloaded as `.qsign.json` and can be independently verified in the Verify Signature tool.

This is cryptographic tamper evidence, not an accredited CA-issued DSC/PAdES certificate. To claim a qualified/legal digital signature, integrate a certificate authority or remote signing service and embed a real X.509 certificate chain.

## Conversion backend

```bash
cd server
python -m venv .venv
# Windows:
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn converter_api:app --host 0.0.0.0 --port 8000
```

The backend uses LibreOffice, qpdf, Ghostscript and Tesseract for operations that need them. Simple/native documents can be very fast, but scanned PDFs, OCR, large page counts and Office cold-starts can exceed 2–5 seconds. The project avoids artificial delays and uses native extraction before OCR fallback; an exact 2–5 second guarantee for every arbitrary file would not be technically honest.

## Optional signing-request email

`supabase/functions/send-signature-request/index.ts` can create signer tokens and send email through Resend.

Set Supabase Edge Function secrets:

- `SUPABASE_SERVICE_ROLE_KEY`
- `SUPABASE_ANON_KEY`
- `APP_URL`
- `RESEND_API_KEY`
- `EMAIL_FROM`

Deploy the function with the Supabase CLI.

## Production checklist

1. Configure Supabase URL/key.
2. Run all migrations.
3. Enable Google OAuth.
4. Configure SMTP.
5. Configure UPI payment verification.
6. Install backend conversion engines.
7. Set `VITE_CONVERTER_API_URL` to the production converter API.
8. Deploy the frontend.
9. Update Google OAuth and Supabase redirect URLs to the production domain.
10. Test login, password reset, credits, conversions, signatures and admin statistics.
